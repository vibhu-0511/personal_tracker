Ask 1 · Responsive

One codebase, three form factors

Today Forge is a phone app that happens to open on bigger screens. The fix is not three layouts — it is one shell that changes its navigation pattern and column count based on container width, plus an input model that stops assuming a mouse or a finger.

What the audit found

Blocks desktop / iPad today

  • .app { max-width: 640px } and .tab-bar-inner { max-width: 640px } — on a 1440px monitor Forge is a 640px strip; on an iPad Pro it is a phone column with dead margins.
  • 1 @media rule in 1,139 lines of CSS (prefers-reduced-motion). 0 width breakpoints.
  • 20+ :hover rules with no (hover: hover) guard → hover state sticks after a tap on iPad.
  • No :focus-visible styles → keyboard / Magic Keyboard users get browser defaults only.
  • FAB offset is calc(64px + safe-area) — hard-codes the tab-bar height, so it breaks the moment nav moves to a side rail.
  • DSA Mastery Map is a separate 8,320-line page outside the shell, with its own layout.

Already right — keep

  • viewport-fit=cover + env(safe-area-inset-*) on the shell and tab bar.
  • 100dvh app height (survives iOS Safari toolbar collapse).
  • CSS custom-property tokens + data-accent themes → theming is already centralised.
  • prefers-reduced-motion honoured.
  • Tabs are code-split (lazy()) → desktop adds panes, not weight.
  • Local-first store → a second device is just another client of the same sync path.

Design rule: by container width and input type, never by device name

iPad windows can be anywhere from a ~320px Slide Over to a 1366px full screen, and rotate live. A "tablet layout" keyed to iPad is wrong half the time; a layout keyed to available width is right all the time.

/* input model */

2.4 Reconcile rule, and where it loses data

This is decideSync() from src/sync/logic.js. It is correct and well tested — for one writer per key at a time. Two devices editing different tasks in the same list fall into the "newer wins" branch and one edit disappears.

Weak points of sync v1

  • Lost edits: phone renames task A offline, laptop adds task B offline → whichever syncs last overwrites the other's whole list. Try it in Lab 1 →
  • Payload grows with history: every keystroke-level save re-uploads the entire expenses blob; a year of spends is pushed to change one row.
  • Clock trust: Date.now() from each device decides the winner; a phone with a wrong clock silently wins forever.
  • No history: no way to see or undo "what did sync overwrite?" beyond the one-time __pre_sync_backup.

Sync v2 — per-record rows, same LWW idea, finer grain

create table tasks (
  id          uuid primary key,
  user_id     uuid not null references auth.users,
  body        jsonb not null,
  updated_at  timestamptz not null,   -- server clock wins ties
  deleted_at  timestamptz,            -- tombstone, not DELETE
  device_id   text not null,
  rev         bigint generated always as identity
);
-- same shape for habits, expenses, loans, goals, notes…
-- client pulls "where rev > last_seen_rev" (cheap delta)
